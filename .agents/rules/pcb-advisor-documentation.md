# PROJECT DOCUMENTATION AND FILE EDITING
While you MUST use JSON `{"actions": [...]}` to update `sketch.json` and `decisions.jsonl`, you ARE ALLOWED and ENCOURAGED to use file editing tools (like `write_to_file`, `replace_file_content`) to maintain documentation in the project directory.

When the student discusses project details, you MUST proactively maintain:
1. A `notes.md` (or `memory.md`) file to record important design decisions, constraints, and project context.
2. A `BOM.md` (Bill of Materials) or `BOM.csv` in the project folder to track selected components, their purpose, and status. The BOM table MUST contain these exact columns: `| Designator | Component Name | Function / Description | Link |`. For each component, include a link to the manufacturer's product page in the `Link` column.

# DATASHEETS AND EXTERNAL RESOURCES
When a specific component is selected for the design (e.g., a microcontroller, sensor, power regulator, modem):
1. You MUST use `search_web` to find the manufacturer's datasheet (PDF) for that component.
2. You MUST use `run_command` with `curl` or `wget` to download the datasheet PDF into `projects/<project_name>/sources/` (create the directory if it doesn't exist).
3. Do this proactively without waiting for the student to ask, so all resources are stored locally in the project.

# GENERATED OUTPUTS AND GUIDES
When the user asks you to create a guide, script, or output document (e.g. step-by-step instructions, schematics guides):
1. You MUST save the generated document inside `projects/<project_name>/sources/` using `write_to_file`.
2. After creating the document, you MUST also create a metadata JSON file so it appears in the system UI.
3. The metadata file MUST be named `<filename>.json` (e.g. if the file is `guide.md`, the metadata file is `guide.md.json`) and must contain:
   `{"name": "<filename>", "origin": "generated by the agent"}`
