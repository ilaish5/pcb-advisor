# UI spec: the workspace (user, 2026-10-11)

Principle: **planning happens together (student + agent) outside Altium; the student enters Altium to implement.**
Agent outputs and user decisions live in the workspace. Placement and routing previews are the main products.

## Tabs

| # | Tab | What it must do |
|---|---|---|
| 1 | **Idea** | Built with the student. A simple **editable block diagram** so the agent and the student share one language. Requirements summary. The diagram is easy to edit (add, rename, move, link and delete blocks directly with the mouse). Proposals arrive on the diagram. No check against course or final-project guidelines (removed by the user, 2026-10-12). |
| 2 | **BOM** | Interactive parts table: update and swap parts; datasheet link per row; live availability indicators, unit prices and cost per board from JLC; open a chat on one part; short note on the part's role in the circuit; risk flags and in-stock alternatives. |
| 3 | **Schematic** | Interactive preview generated by Python from SchDoc or netlist. One-click questions on a specific part or net connection ("Ask about this"). |
| 4 | **Placement & routing** | Interactive preview (outline, pads, layer toggle, placement plan overlay, critical-net routing plan), click a part or net and ask. |
| 5 | **Rules** | JLC manufacturing preset rules, extra rules, diff of board rules against preset, `.RUL` export with 4-step Altium import guide, and engineering calculators (IPC-2152 trace width, voltage divider, LED resistor, via current, microstrip impedance). |
| 6 | **Altium outputs** | Ready OutJob generator and exports (Gerber RS-274X, NC drill, JLC BOM, CPL, schematic PDF), and IntLib library build script. In-app viewer opens exported and reference files directly. |
| 7 | **Final manufacturer checks** | JLCDFM report ingest (PDF to slice images), triage table (severity, section, check, counts, layer), and chat to triage findings as real issues or false alarms. |

Always available: **in-app file viewer** (PDF, image, text/markdown, CSV, Altium summary), **project knowledge base** (Sources: open files, upload files to it), **Settings**, and chat.

## Settings

Link to the Altium project: **project name, path, Altium location, PcbDoc pick, output folder**, and recent projects from the registry (read-only local access).

## Behaviour rules

- The agent **guides the user at every stage**: what is done, what is next, how to do it.
- **"Every claim needs a source" must not become friction.** Show the source as a small inline tag in the answer;
  one click opens the file at that place; no pop-ups, no confirmation, no interruption. A claim with no source is
  marked as unverified instead of blocking the answer.
- The presentation does not show the benchmark/tests (user decision).
