## Findings

- [FRICTION] Chip "Help me with the next step: Confirm the idea" on an EMPTY project: S0-03-new-project.jpg. Confirm idea is disabled (greyed) and nothing is agreed, yet the first chip tells the student to confirm. Same chip shows in S1-02 and S1-03 while a draft is unsaved (Confirm is not yet the real next step: Save is). Cause: `chatSuggestionItems()` ui/js/chat.js:617 takes `stages[].next.label` from the server; no state check for "nothing described yet" or "draft unsaved". Fix: on an empty idea show "Describe my board" / starter prompt; with unsaved draft show "Save the draft".
- [FRICTION] Two-step commit is invisible until the agent says it: Save, then Confirm idea (S1-02..S1-07). Agent text ends every turn with "Next: press Save on the Idea page, then Confirm idea." (S1-02, 03, 04, 05). The student must read that, go to the page, click Save, click Confirm. Also S1-03 offers a "Confirm idea" button in the chat while the draft is unsaved. Fix: one primary button in the draft bar "Save and confirm" (or Confirm idea auto-saves the draft); drop the repeated "Next:" sentence when a button already says it. Source: ui/js/views/idea.js:142-164 (header primary + draft bar), chat "Next:" line comes from the agent prompt.
- [FRICTION] The page lags behind the chat until Save: S1-03 and S1-04. The agent says "4 layers, 45x35" but the Copper layers selector still shows 2 and the description paragraph is the OLD text (I2C for both, one LED) while the diagram already changed. The student had to spend turn 4 (~30 s, S1-05) just asking to rewrite the description, then Save again (v3). Cause: the diagram updates live but description/layers live in the draft, shown only after Save/refresh (idea.js:151-171; layers select reads the saved board, idea.js:221-240). Two sources of truth on one page looks broken. Fix: the draft values (layers, size, description) show immediately, tagged "New/Changed" (the tag exists, idea.js:171, but the description row is not updated until the agent rewrites it); and the agent must rewrite the description itself whenever requirements change, not wait for the student to ask.
- [FRICTION] "Draft - 32/35/42 changes since your last save": S1-02..S1-04. Numbers jump by dozens for one chat turn; the count is meaningless and looks alarming. Fix: say "Draft, not saved" without a count, or count requirements added/changed only. Source idea.js:157.
- [FRICTION] Wait time and feedback: S1-01 shows only "Thinking - 23 s / Steps (7)" while the 12 requirements are built; answers take 30-75 s. The progress label is honest but gives no result preview; the diagram stays empty with "Double-click to add a block" until the end. Acceptable for an agent, but the empty-canvas hint competes with the work in progress. Fix: stream the diagram, or replace the hint with "The agent is drafting..." while busy.
- [FRICTION] Chat text load, first answer: S1-02. A long assumption paragraph, 3 numbered questions each 2-3 lines, plus 12 green chips "Idea proposal: Power / Regulator / MCU / ..." that wrap into 4 rows. The chips add no information (they are source tags for requirements already in the list above) and push the answer off screen. The owner dislikes long text. Fix: collapse the proposal tags into one "12 requirements proposed" tag that opens the list; keep 3 questions to one line each. Source: tag rendering in ui/js/chat.js (grep "Idea proposal").
- [FRICTION] Stacked chip rows at the bottom of every turn: S1-03..S1-07. Under each agent answer: proposal chips, "Undo diagram change", "Confirm idea" and a separate row of 3 suggestion chips ("Help me with the next step", "What is still open?", "What should I decide first?"). Three controls say the same thing. Fix: one suggestion row, only the single best next action.
- [FRICTION] "What should I decide first?" and "What is still open?" are permanent generic chips (chat.js:588) shown in every idea turn, even in S1-07 after the idea is confirmed (everything decided). Hide when the idea is confirmed; the good chip there is "Propose the parts" (S1-07). Fix: after confirm show only the next-step chip.
- [FRICTION] Chat wording is dense for a student (S1-02): "assumed" in every line, acronyms and app-note numbers in the questions. Fix: show "assumed" as a visible badge in the requirement list and keep chat questions to one short line each.
- [FRICTION] Setup: project switcher list is very long and "New project" is at the very bottom (S0-03a; student log: scrolled to bottom, 45 s timeout while page busy). Fix: "New project" as a fixed first row or a "+" button next to the switcher. Source: switcher menu in ui/js/shell.js (grep "New project").
- [FRICTION] Context leak across projects: S0-01/S0-02 show Antigravity chat of the old "demo" project with footer "Antigravity CLI", and the engine change in Settings is global ("Saved") while the chat footer of the open project only updates later. For a student starting a new project the old chat/state is visible until the project is switched. Minor: the black banner "not linked to an Altium project" (S0-02) at the top of Settings is fine but alarming on a project the student is just leaving.
- [COSMETIC] Engine/model footer under the input "Claude Code CLI - opus" (S0-03..S1-07) is tiny grey text; fine as info, but the student has no clue it is switchable from there (they must go to Settings). Cosmetic.
- [COSMETIC] "Previous version" button (S1-06) appears in the same slot as Save/Revert and its meaning ("Bring the previous saved version back as a draft", idea.js:164) is not obvious; only the tooltip explains. Label "Undo last save" would be clearer.
- [COSMETIC] Board constraints row (S0-03: Holes 3.2 mm, 3.5 mm from the corners, "Add 4 mounting holes") appears on the Idea page before anything is described; it adds noise to the first screen. Move under an "Advanced" fold until the board size is set.
- [COSMETIC] Diagram labels are tiny at the fit zoom (52-55%) in S1-02..S1-07; readable only after zoom. A min-size or larger default is better. Source ui/diagram.js (fit zoom).
- Good: the new-project dialog is a single field + Create (S0-03a); Idea page empty state is clear ("Describe the board in a few sentences", "Start from template"); the requirements list + diagram + datasheet-cited claim "STM32F411CEU6.pdf - The USB OTG full-speed controller requires a dedicated 48 MHz clock" is exactly the inline source tag the UI spec asks for (S1-03); Undo diagram change is one click; after Confirm the header button becomes "Next: BOM" and the chip becomes "Propose the parts" (S1-07), a correct, clear hand-off.

## Student confusion log: answers (C1..C17)
Verdict key: REAL = needs a fix, PARTLY = minor, NOT = not a UI problem.

- C1 REAL (FRICTION). The app opens on the last project (here the old "demo" with its long chat), no start screen. A first-time student has no entry point. Cause: boot restores last project (ui/js/boot.js / shell.js navHTML). Fix: when the last project is old or there is none, show a start card "New project / Open project"; at minimum a "+ New project" button in the sidebar.
- C2 PARTLY. The black banner is shown once per project (ready.js:21), correct to warn, but it was seen on the project being left. Check the banner on the new project at stage 3-4; wording "nothing can be drawn or read from Altium" is clear. Fix: add a one-click "Create an Altium project" in the banner itself (the action exists in Settings, pages.js:363).
- C3 REAL (small). Engine switch changes the Model silently and the chat footer lags (chat.js:855 updates #chat-engine only on the next redraw). Fix: redraw the footer on the same "Saved" and write "Saved. Model: Opus".
- C4 REAL. "New project" is under a separator at the bottom of the switcher list (shell.js:164) below ~30 projects; the Find-a-project search exists but nothing says so. Fix: put "New project" as the first menu row, or a "+" icon next to the switcher.
- C5 REAL (FRICTION). The 45 s freeze before the dialog (askText in shell.js:633) may be page busy (4 s nav redraw plus a long project list); no feedback. Not reproducible from the screenshots alone, mark unverified; fix: the dialog should open before any network call.
- C6 REAL. Copper layers defaults to 2 with no hint (idea.js:239-240 only has a tooltip). A wrong default costs a whole re-plan. Fix: a one-line prompt "Choose 2 or 4 layers" shown while nothing is agreed, or the agent's first question asks it (it did not in S1-02: it assumed 2).
- C7 REAL. "Thinking 23 s / Steps (7)" with no named step and no estimate (S1-01); answers took 30-75 s. Fix: show the current step in words ("Reading datasheet", "Drawing diagram") and a typical time; steps list open by default while busy.
- C8 REAL (UI side only). Twelve requirements all tagged "assumed" look like decided facts, and Confirm idea is one click away without any hint that guesses remain. UI fix: a visible count "12 assumed" next to Confirm idea (idea.js:142-146) and the questions shown as one-click choice buttons. (What the agent chose to assume is out of scope.)
- C9 REAL. Same as my chat-text finding: 13 "Idea proposal: X" chips. Fix: collapse into one tag; put the 3 questions first, not at the end (chat.js:451 maps the tags).
- C10 NOT (browser tab died). But the recovery was good. Minor: after reload the user message and "Working ... 33 s" were shown, which is the right behaviour.
- C11 OUT OF SCOPE for the designer (technical wording; forwarded to the engineer). UI side: stock/price text appears in the idea chat, a stage mismatch. Original note: technically wrong wording. "added an external crystal for the 48 MHz clock" implies a 48 MHz crystal; the F411 gets 48 MHz from the PLL off HSE. Also JLC stock/price inside the idea chat is out of stage. This is an agent-prompt cause (idea stage prompt), not a UI file; the engineer should rule on the wording. Fix: idea prompt forbids stock/price and requires "PLL derives 48 MHz from HSE".
- C12 REAL. Layer count disagrees in three places (selector=2, diagram frame "2-layer", requirement "4 layers") until Save. Cause: selector reads the saved board.layers (idea.js:221-240), diagram text is regenerated later, requirement list shows the draft. Fix: draft values drive all three at once, or mark the selector "unsaved: 4".
- C13 REAL. Description paragraph contradicts the requirements until the student asks for a rewrite. Fix: after any change turn, the agent rewrites the description itself (same turn) and the page marks the description "Changed" (tag exists at idea.js:171 but descProposed() is only set by the agent).
- C14 REAL. Confirm idea is enabled with an unsaved draft and the page does not say what it confirms (idea.js:146, onAct 'confirmidea' idea.js:686 posts confirm without saving). Risk: confirm an old version. Fix: Confirm saves the draft first and says "Saved v3 and confirmed", or is disabled until saved. Best: one button "Save and confirm".
- C15 REAL. Holes are stated as "assumed" in a requirement while the Board constraints fields stay empty and a separate button adds them: the same fact in two places that do not sync. Fix: remove the separate row, or let the requirement fill the fields.
- C16 OUT OF SCOPE (content). UI side only: assumed items are mixed into the summary paragraph with no mark. Original note: the agent added "USB DFU as a backup" that the student did not ask for. It is marked as assumed in the list, but the summary paragraph states it as fact. Fix: descriptions may only restate agreed items; assumed items marked "(suggested)".
- C17 REAL (small). After Confirm, nothing says what is now locked or that edits are still allowed. Fix: one sentence under the header "Confirmed. You can still edit; later stages will re-check" (idea.js:141-142 area).

## Score and fixes
Score S0+S1 (UI/UX only): 6.5/10. The screens are clean and the next step after Confirm is clear; the score is held back by the Save-then-Confirm detour, the page lagging the chat (layers/description disagree), 30-75 s waits with a bare 'Thinking' label, and chat text/chip clutter.

Top 3 fixes:
1. Draft values (layers, size, description) must show at once and the agent must rewrite the description itself; replace Save + Confirm with one "Save and confirm" action (idea.js:142-171).
2. Cut chat clutter and make the first turn ask, not assume: collapse the "Idea proposal: X" tags into one, show a single suggestion row, hide generic chips after confirm (chat.js:588-620).
3. Fix wrong/stale suggestion chips: no "Confirm the idea" on an empty or unsaved idea (chat.js:617); put "New project" at the top of the switcher (shell.js).

## Out of scope (not judged here)
- Which MCU, crystal values, 4-layer choice, assumptions the agent made, and the 48 MHz clock wording (C11): engineering/lecturer matters, forwarded.
- The student's choices in messages 2-3.

## Round 2 (S1-08..S1-17, confusions C18-C28), UI/UX only

Correction to my round 1: the Confirm idea tooltip says "Saves the draft and marks the idea as agreed" (idea.js:145), so Confirm does save the draft. The student never learned this because nothing on screen says it (C14 stays valid as a clarity problem, not a data-loss risk).

- C18 REAL. 190 s of "Working with the documents / Steps (12)" (S1-08), no estimate, and the header still shows "confirmed" and "Next: BOM", so it is unclear whether a question touches the confirmed idea. Fix: name the current step with elapsed and a typical time; a Q&A turn that changes nothing needs no state change, but a one-line "Question only, the idea is unchanged" under the answer settles it. Same cause as C7 (chat progress block).
- C19 REAL (UI wording), cause partly the harness. The red box "the agent edited system files: ... they were restored. System bugs go to the developer as a report, not a patch" (S1-09) is unreadable for a student: "system files", "restored" and "agent" are not explained, and it shows file paths. It came from scripts/tool_guard.py:239 (the guard reverts files the agent changed). Here the files were the student's own notes written in the repo while the agent ran, so the guard misattributed them; that is a test-setup artifact, but the wording problem is real for any student. Fix: plain sentence ("I tried to change a protected file; I undid it. Nothing of yours was changed") and never revert a file the agent did not write (evidence the guard cannot tell who edited, a possible data-loss bug for the engineer). Note also the text says "to the developer" on screen vs "to the student" in tool_guard.py:239: check which build is served.
- C20 REAL. The answer is honest (red "Not all of this happened: 1 step failed" with the unknown stated), which is good; but it ends by asking the student to download a PDF into "the project's sources folder" with a bare URL in the text (S1-09). Fix: a one-click "Add this document" chip next to the URL (it already exists as Sources > Add > From URL, pages.js), and the answer should say where the sources are ("Sources page").
- C21 REAL (FRICTION, close to BLOCKER for the flow). Sources > From URL runs "Fetching the document" ~70 s (pages.js:544), then the spinner disappears and the list is unchanged; no visible failure (S1-12). Silent failure is the worst feedback state. Fix: a persistent red line "Could not fetch it (timeout). Upload the PDF with Add > Upload" with the Upload button inline, and a shorter timeout (about 20 s). The grey "1 in this project" list also mixes 41 shared course files into the same table by default; the "Project" filter is not the default (S1-12). Cosmetic: default to Project.
- C22 REAL. 14-row pin table plus long text in a 300 px chat column, 3 screens of scrolling (S1-13..S1-15). The owner dislikes long text. Fix: tables and long answers render on the page (Idea page "Pin table" section or the viewer) and the chat shows two lines plus "Open table". The table also sits under the page fold: in S1-15 the row text wraps and the first column is wider than needed.
- C23 REAL (FRICTION). "Altium's Update PCB will offer to remove them: answer No" shown at the Idea stage (S1-13): an instruction for a step many stages away. Fix: show it where it applies (at Layout / Update PCB), not in the Idea constraints box.
- C24 OUT OF SCOPE as engineering (pin consistency, forwarded to the engineer). UI side: when the agent corrects an earlier answer the chat gives no "Corrected" mark; the old answer stays above unchanged. A "Changed from earlier answer" tag would help.
- C25 PARTLY. "should fit ... (planned)" is wording of the agent; the UI shows no fit status. A small status chip next to Board size ("fits / not checked yet") would give the yes/no the student wanted. Low priority.
- C26 GOOD. Keeping "(assumed)" until the student confirms is a good, visible safeguard. UI problem: it is only visible at the end of a long answer. Fix: show assumed/unconfirmed as a badge list on the page next to Confirm.
- C27 REAL, the main round-2 finding (FRICTION, borderline WRONG for state clarity). After saving v4 the header still says "confirmed 27 Nov 2026" and only offers "Next: BOM" (S1-17; idea.js:141-142 shows the confirmed state whenever I.confirmed is set, whatever D/version changed). The agent said "press Save, then Confirm idea", but the Confirm button is hidden once confirmed. The student cannot tell whether v4 is confirmed. Fix: compare the saved version with the confirmed version; if different, show "Changed since confirmed" (warn tone, like the "proposed" count at idea.js:132) and a primary "Confirm again" button. The page must never say "confirmed" for a version that was not confirmed.
- C28 REAL. The agent's instructions disagree with each other and with the buttons ("Save then Confirm", "Save confirms them too", S1-16/S1-17). Fix: the "Next:" sentence should come from the UI state, not free text from the agent; with C27 fixed there is one rule: Save (and Confirm again when it is shown). Also the diagram MCU block still reads "STM32 (MCU)" (S1-17), a stale label next to a chosen part; cosmetic.

New UI findings in round 2:
- [FRICTION] The "Draft - 19 changes since your last save" bar returns on a confirmed idea (S1-13/S1-15) with Next: BOM still active above it: two conflicting calls to action. Fix: while a draft is open on a confirmed idea show "Save" / "Revert" only and disable or relabel Next.
- [COSMETIC] Chip block under each agent answer is now 10+ tags (S1-13, S1-16/17: "Idea proposal: ..." plus a long "Idea constrain: add h1 (proposed; the student confirms with Save)" tag). Internal wording ("constrain", "h1") leaks into the UI. Source ui/js/chat.js:451.

Round 2 score (UI/UX only): 6/10. Good: honest failure text, sources inline, plain "Saved" toast. Held back by the silent failed fetch, the confusing confirmed/draft state after edits, and long answers with tables in the narrow chat.

Top 3 fixes for round 2:
1. Show "Changed since confirmed" + "Confirm again" when the saved version differs from the confirmed one (idea.js:132-146).
2. Sources fetch: visible persistent failure with an Upload button and a shorter timeout (pages.js:544).
3. Move long tables/answers to the page, and rewrite the guard message to plain words (chat render; scripts/tool_guard.py:239).
