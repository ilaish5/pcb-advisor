## Findings

- [FRICTION] Approve does not change the numbers the student sees: S2-08, S2-13, S2-15. After "Approve all" the BOM stays "28 lines / 28 parts / Qty 1 everywhere"; the chat says 51 parts. Header "N parts" counts reference designators, not the Qty column, and the Qty cell is not updated by a card that gave only a count (student log C36). The student lost two rounds. Fix: one rule for the table: Qty = number of refs, header parts = sum of Qty, and a card that cannot set refs is rejected visibly, not applied. Source ui/js/views/bom.js (metaLine near :126-135, row render :112); proposal cards ui/js/chat.js:195, ui/js/kit.js:181.
- [FRICTION] Code-style warnings in the chat: S2-08, S2-13. "bom.propose applied with warnings: R1: the role 'CC1/CC2 pull-downs' names 2 parts but there is 1 (R1): add the missing refs or change the role". Internal action name, no button. Same warning reappears for R1, R5, R11, C1 after the next answer although the student already approved (S2-13). Fix: plain sentence + one "Fix quantity" button; warnings clear when the refs match. Source ui/js/chat.js:522,535 (`applied with warnings`, `chatActLabel`).
- [FRICTION] Two states at once: S2-13 shows "28 parts" in the header, "5 proposed changes waiting for your approval" on the page, and "Done: 6 BOM lines" plus orange warnings in the chat. The student cannot tell whether the changes are applied. Fix: while a proposal is waiting show "28 parts (51 after approval)"; chat card for a pending proposal says "waiting on the page", not "applied".
- [FRICTION] "Red dot + number" tag "Check qty" is small and sits next to "Missing" (S2-15, S2-08). Easy to miss and it is not clickable. Fix: make the tag a button that opens the row with the fix. Source bom.js:112, kit.js:181.
- [FRICTION] Check stock gives no feedback when there is nothing to check: S2-20, S2-21. For 30 s the button looks unchanged and the header time is old. The code shows "Checking..." only while the call runs (bom.js:119, 459-472) and on success shows no toast when the BOM view is open (bom.js:472), so a fast no-op or a lookup that skips passives with no MPN is silent. Fix: always end with a one-line result under the header ("Stock checked 14 lines; 14 passives have no part number: choose them") and keep the button label "Checking..." for at least 1 s. The "Not checked" tag already says "Add an MPN to check stock" in its tooltip (bom.js:54): show it in the row, not only on hover.
- [FRICTION] Numbers change by themselves: S2-08 shows "$49.76 per board (3 of 28)" then "$43.88 (14 of 28)" with no sign that stock is being checked in the background. Title text exists (bom.js:129 "checked in the background") but only as a tooltip. Fix: small "checking 14 lines..." with a spinner in the meta line while t.checking > 0.
- [FRICTION] Long waits with a bare label: S2-04..S2-06 "Searching JLC", "Working with the documents 167 s", about 4 min for the first proposal; S2-10..S2-11 about 3 min. Same finding as stage 1 (no named step, no estimate). The BOM page itself stays empty ("No parts yet", S2-03) during the wait. Fix: show the proposal rows as they arrive, or "Agent is choosing parts: 12 of ~28 so far".
- [FRICTION] Chat text load and wide tables in the narrow chat: S2-13 (about 40 lines, 5 items plus a current table), S2-18 (a table of 11 rows with 6 columns, horizontal scroll inside the chat), S2-07 (28-row card in the chat AND the same 28 rows on the page, i.e. the same proposal twice). The owner dislikes long text. Fix: the chat shows "28 parts proposed, review on the page" with a link; the full card only on the page. Source ui/js/chat.js:195 (proposal card), same data as the BOM page.
- [FRICTION] A review chip can start work: S2-29, S2-30. The chip "What is wrong in the BOM (28 open), and how do I fix it?" led the agent to start "Build library" without being asked; the build failed with "No Altium project is linked to this project yet. Create one first" and a bare "Retry" link. Three UI issues: (a) the chip wording "28 open" suggests 28 problems when they are library items (source chat.js:615, `here.open`); (b) a diagnosis question should not start a build: ask first with one button; (c) the error should offer "Create an Altium project" (Settings has it, pages.js:363), not Retry, which cannot work. Note: this is also an agent-behaviour issue for the engineer; the UI part is wording and the error action.
- [FRICTION] Build library is the filled primary button in the BOM header from the first line (S2-08, S2-18..S2-28) although no Altium project is linked (C29) and nothing says it will fail; it looks like the next step before the BOM is approved. Fix: while Altium is not linked show "Link Altium to build the library" as the primary action. Source bom.js:121-124.
- [FRICTION] Unlinked Altium is silent until it fails: C29, S2-02. The black "not linked" banner is shown once and is dismissable; the student never sees it again until the build fails at S2-30. Fix: at the first Build library press, or on the BOM page header, "Altium not linked: Create the Altium project" one click.
- [COSMETIC] Left menu red dot and "6" on Rules appeared after the failed build (S2-30, C39). A badge with no explanation and no board behind it looks like an error. Fix: tooltip "6 rule items to review" or no badge before a PCB exists. Source ui/js/shell.js (stageStatus, :101).
- [COSMETIC] The BOM Ref column shows "C1-C9, C14,..." cut off (S2-19, S2-23, C36) and the "28 lines" next to "51 parts" reads as inconsistent. Fix: wrap the ref list, and relabel "28 lines, 51 parts" with a tooltip "1 line can hold several parts".
- [COSMETIC] The same chip set appears under every answer ("What is wrong in the BOM (28 open)", "Help me with the next step: Review the BOM", "Check stock for the whole BOM") even when stock is already checked (S2-28). Hide done actions.
- [COSMETIC] The footer line "Prices at qty 10, excl. shipping. Checked 27 Nov 2026 01:49. Before you order" is good but small; fee notes "plus $33.77 extended fees" explain themselves well.
- Good: Approve selected / Reject selected / Approve all on one row with counts (S2-07); the honest "Not all of this happened: 1 step failed" red label; stock status tags (In stock / Low stock / Extended fee) with colors are quick to scan (S2-08, S2-28); price per board with extended fee shown separately; the per-row icons for symbol/footprint/3D/pins with a legend.

- C31 REAL. Code-like warnings (chat.js:522,535); add plain wording and a button.
- C32 REAL (small). Background stock updates change the header without a visible state (bom.js:129 tooltip only).
- C33 REAL. Applied vs waiting is shown at the same time (S2-13). One state needed.
- C34 PARTLY. The long answer is a UI text-load problem (chat panel). The SD card current "unknown" is content for the engineer (out of scope for the designer). UI fix: the answer is on the page, 3 lines in the chat.
- C35 REAL. Same as C30/C33; after approve and reload the page must show Qty and parts consistent with what was approved. If the card was applied with a count only, show "Applied, but no refs: quantity not set" in the card, not a green "Approved".
- C36 REAL. Cost the student two rounds; also the cut-off Ref column. See the first finding; the key fix is an error when a card is not applied.
- C37 REAL. No feedback for a no-op or slow Check stock (bom.js:459-472; no toast when in the BOM view). The student could not know why the passives stayed "Not checked": the reason (no MPN) is only in a tooltip (bom.js:54).
- C38 REAL (wording + behaviour). Chip "28 open" misleads (chat.js:615); the agent started a build after a diagnosis question and the error offers Retry instead of the cause. The unrequested build is an agent-behaviour issue for the engineer.
- C39 REAL (small). Unexplained red "6" on Rules (shell.js stageStatus).
- C40 PARTLY. The notes (SD 100 mA unsourced, dim green LED) live only in the chat; the BOM line shows neither. UI fix: a note field on the row ("dim at 680 ohm") so notes survive the chat. The LED/SD content itself is for the engineer/lecturer.

## Score and fixes
Score S2 (UI/UX only): 5.5/10. Good status tags and a clear approve row, but the central number (parts / Qty) disagrees with the chat, two approve rounds were needed, Check stock was silent, and the chat is full of tables and code-like text.

Top 3 fixes:
1. Make the Qty column and "N parts" always match what was approved, and reject (visibly) a card that cannot set refs; one state, "waiting" or "applied" (ui/js/views/bom.js header + row, ui/js/chat.js:195,522-535, ui/js/kit.js:181).
2. Give Check stock and the background stock updates visible feedback with a result line and the reason passives are skipped (ui/js/views/bom.js:54,119,129,459-472).
3. Move proposal tables and long answers out of the chat to the page; fix misleading chip wording and the unlinked-Altium path (build button vs "Create the Altium project"): ui/js/chat.js:195,615, ui/js/views/bom.js:121, ui/js/views/pages.js:363.

## Round 2 (S2-31..S2-57, confusions C41-C48), UI/UX only
Round 2 content: crystals/LDO fix (5 cards), idea updates (v5, v6, v7), 3 LED/SD cards, LDL1117 swap, datasheet attach, duplicate-ref fix, Altium project created.

- C41 REAL, serious (state clarity + control). After Stop on the library build the chat still shows "I'm creating the project and then building the library" with a green "Altium create project" chip and a red "stopped by the student" line (S2-31). Stop ended one step, not the plan. UI fix: Stop ends the turn and the last line reads "Stopped. Nothing else was done" (and lists anything that WAS done); a green chip must never appear for an action that ran after Stop. Source ui/js/chat.js (stop handling near :545, chat-act rendering :522-545).
- C42 REAL. About 6 min wait with "Thinking / Searching JLC 264 s" (S2-32..S2-34): same wait-feedback finding as before, the most repeated friction of the run. The important result (gm_crit calculation, high-drive firmware note) is hidden in the small "Why" column of a card cut off at the right (S2-35). Fix: the card's reason shown as 2-3 lines under the row (wrapped), and a one-line warning chip "Needs firmware: LSE high drive" on the requirement page. Card source ui/js/chat.js:195, kit.js (proposal card). Odd values (2 pF) are content (engineer), but the card should show the formula line "why this value" visibly.
- C43 REAL. The Idea page keeps two current figures (168 mA and 175 mA, S2-40) and an empty "Board size from the idea text" box. UI cause: each requirement is free text edited by the agent, so numbers repeat and drift. Fix: when the agent changes a number, the page lists lines that still contain the old one ("also mentions 175 mA: update?") with one click. Hard to do in UI alone; at least show a "may be out of date" tag on lines the agent did not touch in that turn.
- C44 REAL (UI side). The answer mixes verified and unverified claims with green ticks and "File only, claim not verified" (S2-45, S2-51); the student cannot tell which to trust, and the datasheet attach result (3 may be wrong, 1 scan) shows only as chat chips, not on the BOM page. Fix: one "Datasheets" column or badge in the BOM table per row: verified / unverified / wrong part / scan (read by eye), with the next step in the tooltip. Source ui/js/views/bom.js (row cells) and ui/js/chat.js chip renderer (:451). The SD 200 mA finding itself is content (engineer).
- C45 REAL. The datasheet chip "U5 <- LDL1117S33R.pdf: unchecked (does not mention ME6211A33PG-N)" is shown in green (the chip color for done things) and the check ran against the OLD MPN because the swap card had not been approved yet (S2-51). UI problems: (a) a failed or unchecked state must not use the green chip style (chat.js:451 chip tone); (b) the attach should be shown as "waiting for the part change" until the card is approved; (c) the Rules badge went 6 -> 8 with no board (S2-51 left menu): same unexplained badge as C39. Praise: the card "U5: change the 4 fields" (old crossed out, new beside it, S2-50) is the best pattern in the product; use it for every change card (also qty and duplicate-ref changes).
- C46 REAL (repeat of C13). Goal paragraph still says "ME6211, SOT-89" after the LDO swap (S2-52). The part change updated the requirement but not the description. Fix: description is regenerated, or the part names in it are links to the BOM line so they cannot go stale; at least tag it "Changed parts: may be out of date" when a BOM part named in it changed. Also two different Tj numbers (86 vs 80 C) are a content issue (engineer).
- C47 REAL, important. A card created a duplicate ref (R4 on two lines) and the approve step accepted it; header said "53 parts" for ~10 min until the stock check caught it (S2-55). Fix: refuse the approve with a visible message ("R4 is already on another line") before applying, and show a "duplicate ref" tag on both rows (bom.js:112 tag position). Note: the stock check, not the BOM, caught it, which means the validation exists in one place only; the BOM page should always display it. Also the same card appears twice at once, on the page and in the chat (S2-55), a repeat of the text-load finding.
- C48 REAL, serious. Altium project and PcbDoc were created by the agent as a side effect of a review question after the student pressed Stop (S2-57, Settings > Altium). The student never clicked "Create an Altium project" (pages.js:363). The Approvals mode says "Ask for anything that changes the design or the build" (S2-57), so this should have been a card. Fix: anything that creates files outside the project must show an approval card first; the generic system cause is the agent calling the create tool without the approval gate (engineer to check the approvals path). UI side: after such an action, a toast "Altium project created: Final-E2E-4L.PrjPcb" with Undo.

New UI findings in round 2:
- [FRICTION] The instruction and the buttons disagree again: the answer says "Next: approve the U5 card on the BOM page" (S2-51) while the card with Approve is in the chat panel; the student is on the Idea page. Fix: card is approvable where it is shown, and the text says "Approve the card below".
- [FRICTION] Idea page and BOM badge changes: while the student works on Idea, the BOM nav badge changes 28 -> 30 and the Rules badge 6 -> 8 without explanation (S2-45, S2-50, S2-51); badges with changing numbers and no tooltip look like errors. Source ui/js/shell.js (stageStatus :101).

Round 2 score (UI/UX only): 5.5/10 (unchanged). Better: the change-card with old and new values, and an honest stock check. Worse: the agent acts after Stop, silent side effects (Altium project), duplicate refs accepted, and unclear verified/unverified states.

Top 3 fixes for round 2:
1. Stop must stop the whole plan, and any file or project creation must go through an approval card (chat.js stop handling; approvals path for the create tools; show a toast with Undo).
2. Validate cards before applying (no duplicate refs, qty = refs) and show the result on the BOM page (bom.js:112 and header); reuse the "old to new" card style everywhere.
3. One visible verification state per datasheet/claim in the BOM table, never in green when unchecked; wrap the card reason text instead of cutting it (chat.js:451, kit.js proposal card).
