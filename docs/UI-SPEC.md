# UI spec: the workspace (user, 2026-10-11)

Principle: **planning happens together (student + agent) outside Altium; the student enters Altium to implement.**
Agent outputs and user decisions live in the workspace. Placement and routing previews are the main products.

## Tabs

| # | Tab | What it must do |
|---|---|---|
| 1 | **Idea** | Built with the student. A simple **editable block diagram** (the user has an example image; ask for it again if missing) so the agent and the student share one language. Requirements summary. The diagram must be easy to edit (add, rename, move, link and delete blocks directly). No check against course or final-project guidelines (removed by the user, 2026-10-12). |
| 2 | **Parts** | Interactive table: update and **swap** parts; **datasheet link** per row; **availability indicator** from the manufacturer; **open a chat on one part** (the datasheet is attached to the question automatically); a **short note on the part's role in the circuit**. |
| 3 | **Schematic** | Preview generated by Python. **One-click questions** on a specific part or connection (the question carries what was clicked). |
| 4 | **Placement and Routing** | Same idea: **interactive preview** (zones, connector directions, critical-net routing plan), click a part or net and ask. This is the main output area. |
| 5 | **Altium outputs** | Every relevant export file, schematic to Gerber, including **both parts tables** (manufacturer format and full). **Open files in the interface** (datasheet, schematic, reference files). |
| 6 | **Manufacturer check** | Final checks at the manufacturer. The agent guides how to run them; the user **uploads the results** and discusses them with the agent. |

Always available: **project knowledge base** (open files, **upload files** to it), **Settings**, chat.

## Settings

Link to the Altium project: **project name, path, Altium location**, and whatever else the script needs to address the
right project (see PRODUCT-PLAN decisions 21-22 for local-copy only).

## Behaviour rules

- The agent **guides the user at every stage**: what is done, what is next, how to do it.
- **"Every claim needs a source" must not become friction.** Show the source as a small inline tag in the answer;
  one click opens the file at that place; no pop-ups, no confirmation, no interruption. A claim with no source is
  marked as unverified instead of blocking the answer.
- The presentation does not show the benchmark/tests (user decision).
