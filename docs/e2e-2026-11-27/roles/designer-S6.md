# Designer review - Stage 6 (Rules, Route, DRC, Fix the board) - UI/UX only

Scope: only what the student sees in the browser. Board engineering and the student's choices are in "Out of scope" at the end.

## Video highlights
- S6-16-routing-3m39 | Timer ticks, but no step, no tracks: hang or work?
- S6-17-route-rejected-4-short-circuits | Six minutes thrown away; banner has no button, no next step.
- S6-29-check-board-drc-421 | Green check mark over 421 violations.
- S6-32-answer-table-fixes | Every fix says "do it in Altium"; no button here.

## Score: 5 / 10 (UI/UX only)
Good: the busy banner states that the step cannot be cut short; Replace / Keep it is a clear two-button consent; the 421 is already grouped by rule in one sentence; the rejected route is restored from backup and says so. Bad: the app is silent for 5-6 minutes, a rejected route is a dead end, "success" colors sit over 421 findings, and every fix path leaves the browser with no tracked state.

## Findings (PROTOCOL format)

- [WRONG] Check board reports 421 violations in a GREEN success banner: S6-29 (green banner, check mark, "total 421"), while the sidebar shows red "421" next to it and the same sentence on page load is "bad" tone (previews.js:357 `drcSummary` -> 'bad'). The live answer path sets `kind: warnings.length ? 'warn' : 'ok'` (previews.js:587) from the step's warnings, not from the violation count, so a DRC step that "ran fine" is green whatever it found. Why it matters: the student reads the check mark as "board OK" (same family as the green "Pins: nothing to verify" in S4). Generic cause: the banner tone is derived from "did the step run", not from "what did it find". Fix: after drc/route, set the tone from `drcSummary(S.board_check)` (bad if total > 0), and keep the check mark only for "ran".

- [WRONG] A rejected route is a dead end: S6-17 (red banner "The route does not check out: ... 4 new Short-Circuit violations ... Between Pad H1-(1137.795mil,1137.795mil) on ..." truncated by the banner, then "Show details"). No cause in student words (the short circuits are 4 mounting holes), no button ("Show where", "Ask what to do", "Try again"), no statement of what is kept ("board file put back" is hidden under Show details, S6-18). The student had to find the "Ask" chip in the chat and wait 4 min for an answer (S6-19/20). Why it matters: the most expensive failure in the product (6 min) gives the least guidance. Generic cause: the route error is shown as raw script text (`r.error`, previews.js:588) with a `partial_offer` slot but no per-cause actions. Fix: banner shape "Route rejected, board restored. Cause: <1 sentence>. [Ask the agent what to do] [Route again]" and move the Altium coordinates to details; the first line must say "nothing on your board changed".

- [FRICTION] 5-6 minutes of route with only a timer: S6-13, S6-15, S6-16 (0:05, 2:05, 3:39). The text says "Routing can take a couple of minutes" (previews.js:333 `busy`), but the real time was 5.5-6 min, twice; the preview shows no tracks while it runs and the header buttons are disabled ("Routing" greyed). The student cannot tell a hang from slow work, and "cannot be cut short" removes the only exit. Same pattern as the S4 20-minute silent build. Generic cause: `busy` is a fixed string per step, no server-reported phase. Fix: (a) honest estimate "usually 4-7 minutes on a 4-layer board" with a time-so-far bar; (b) server-reported phase line ("placing tracks", "adding GND/3V3 planes", "checking rules") from the script log the server already keeps; (c) for the first 60 s say what the student can do meanwhile ("you can leave this page; the result will wait here").

- [FRICTION] The 421 are shown as one sentence plus a 16-item warning list, and the chat gets a second copy: S6-27 (beige banner: "Altium DRC ... total 421 (0 clearance before routing)", then "Show 16 warnings", each warning a 60-word paragraph with "Way forward"), S6-29 (the same long paragraphs pasted into the chat as an orange block). Prioritization is missing: 252 mask slivers + 157 silk items (409 of 421) are footprint/library matters; 4 annular ring + 7 board clearance + 1 silk-silk are the ones a student might act on; the order is by rule name, not by "what blocks ordering". Not actionable from the browser: no click on a finding to see it on the preview (the preview in S6-28/29 shows no markers), no filter. Generic cause: DRC results are a text blob (previews.js:481-484 `pv-more` lists), not a table with severity and location. Fix: a "Board check" panel on Layout with 3 groups (Blocks ordering / Fabricator accepts but stricter than the preset / Cosmetic), count per group, each group collapsed; the red sidebar number counts only the first group; the chat gets one line + link, never the paragraphs.

- [FRICTION] Success banner contradicts itself: S6-27 "total 421 (0 clearance before routing)" and the warnings say Board Clearance 5 -> 7; "(0 clearance before routing)" is unexplained to a student. Also "437 total" in the rejection (S6-18) is mostly silk/mask noise. Fix: show only "new from routing: N" and "was there before: M"; drop numbers that need engineer context.

- [FRICTION] "Fix the board" has no tracked state and no in-app action: S6-31/32/34/36 (all fixes begin "open Altium Panels > PCB Rules and Violations", "Next:" always points into Altium; the agent says "I can't move C10, edit pads ..."). The student asked "can you do these for me?" and got a refusal after 2 steps. The product never says on the page, before the question, which of the 421 the tool can fix and which not. Same generic gap as S3 ("tool cannot do this"). Fix: per-group state on the Board check panel: "Tool can fix" (button) / "You fix in Altium" (3 numbered steps + "Done, check again") / "Accept (reason)"; the chat answer then links to it instead of re-explaining.

- [WRONG] No way to accept or waive a finding the fabricator allows: C121 (S6-33: annular ring 0.200 vs rule 0.203 while JLC needs 0.15; U2 mask dam meets JLC but is flagged by the preset's stricter value). The red 421 never clears, so the sidebar/Outputs gate stays red for the whole project. Fix: "Accept with reason" per group, listed under Rules as "Accepted risks" (the DFM page already has "Accepted risks"; same component, same wording); the sidebar badge excludes accepted items.

- [FRICTION] The student is not told whether to continue to Outputs: S6-31/36 end with "Next: open Panels..." and the page header still offers "Next: Rules" on Layout (S6-17, 27, 29) although the student is already past Rules and the Rules page is where Apply happens. Generic cause: header "Next" follows stage order, not state (chat.js:608-617 for the chip, same for the header). Fix: "Next" on Layout after a routed board = "Check results" or "Next: Outputs (421 open, 4 block ordering)".

- [FRICTION] Rules page, first view is alarming and unexplained: S6-03 (red badge "8" on Rules sidebar, "6 missing from the PcbDoc", "2 below JLC minimum" while "Board DRC: not run yet"); the lines "5 differ", "6 missing", "2 below" are 4 stacked lines with no sentence like "These are the board's default values: press Apply rules in Altium". The "Board DRC: not run yet" line sits left of the content column (x=233 vs 257 for the rest), looks like a layout slip (rules.js header block). Fix: one headline sentence with the one action ("Your board still has Altium's defaults. Apply the JLC rules"), align the DRC line, and make the red badge say what it counts on hover.

- [COSMETIC] After Apply, the page flips to "Your board matches the preset" (S6-09) while the "Width wanted" cells still show 0.254 mm and "Drawn: -"; later widths become 0.127 mm (C112). The student sees a value change with no explanation. Fix: a one-line note under Net currents when the width wanted changes after Apply ("changed because the preset minimum is now applied") or keep the column stable.

- [COSMETIC] Chat engine label disagrees with the footer: S6-09 shows "Claude Code CLI - opus" under the last answer while the footer already says "Antigravity CLI - gemini-4-hydrogen-high". Probably an old message after the switch; add "(before the switch)" or hide the per-message label when the engine changed.

- [COSMETIC] "Jump to latest" overlays the last row of the chat table (S6-32), and the 5-column table is cut at "Where / Fix" in the narrow chat (rows "Unknown (inspect..." truncated). Fix: tables in chat render as stacked cards below ~420 px; the "Jump to latest" pill needs a bottom margin above the input.

- [COSMETIC] Internal/doc leaks in the answer: "(checks/board.py)", "(rules.py diff)", "m23-drc.en.md - 23.4 PCB Rules and Violations Panel" links in S6-31/32/34/36. A student does not know what rules.py is. Fix: hide source file names behind a "Sources" popover, as the S2-S5 reports proposed.

- [FRICTION] Place parts consent is good, but the student cannot see what they lose: S6-22 ("The board already has 63 parts or copper objects" - 63 is not a number the student knows; "Keep it" is the dark/primary default although the only way forward is Replace). Fix: "55 parts and 8 other objects (4 holes, 4 keep-outs)" and make the primary button the one the chat recommended.

## Answers to every confusion entry (C110-C122)

- C110: Real UI problem (explanation, not engine). Rules sidebar badge "8" and the red counters in S6-03 are unexplained; the student expected rules to be set at layout start. The page shows the cause only as numbers (rules.js:85 chips). UI cause: rules.js:85 `label/tone` chips without a sentence; Fix: headline sentence + one button, align the "Board DRC" line.
- C111: Partly out of scope (the missing USB pair rule is a tool limit). UI part is real: the Net currents form says "Leave a current empty when you do not know it" but "unknown: default" gives no estimate from the Idea (268 mA peak is on the Idea page). Fix: prefill from datasheet currents with a "from datasheet" source label; the "Extra rules" empty form needs one worked example in student words, not `InNetClass('PowerNets')` in mil.
- C112: Real but small. Apply is fast and clear (S6-09); the changed "Width wanted" after Apply is unexplained. UI cause: rules.js widths column recomputed after loadRules(true) (previews.js:343 `after`). Fix: change note, see COSMETIC above.
- C113: Content (90 ohm, thin tracks) is out of scope. UI problem: a limit of the tool shows up only as an answer in chat (S6-11) with a "Next:" that sends the student to Layer Stack Manager in Altium; the Rules page, where the student is when asking, shows no "not supported" row. Fix: on the Rules page, a short "Not covered by the tool" list (USB 90 ohm pair, stack-up) so it is a stated limit, not a discovered one.
- C114: Real problem. Timer only (S6-13..16), estimate wrong ("a couple of minutes", real 5-7), no phase. UI cause: previews.js:333 `busy` fixed string. Fix: see FRICTION above.
- C115: Real problem. Rejected route is a dead end (S6-17/18). Cause: previews.js:588 `pvNote = {kind: 'bad', text: r.error}`; no actions. The "437 total" is noise from the rule-by-rule DRC string (previews.js:524 `PV_DRC_RE` keeps all).
- C116: Out of scope as engineering (keep-out vs copper). UI part: the same tool offered a feature in S5 and later asks to remove it; the UI had no marker saying "keep-outs are drawn as Top copper, check before routing". A pre-route check on Layout ("Before you route: 3 things") would show it before the 6 minutes are spent. Generic fix: a pre-flight list on the Route button (tooltip or modal) with tool-known risks.
- C117: Mostly fine. The two-button consent works; "63 parts or copper objects" and the dark "Keep it" default are the friction items (previews.js:331 `ask`). Fix: count breakdown, recommended button primary.
- C118: Real problem. "Routed" banner is amber with the number 421 and the contradictory "(0 clearance before routing)" vs "5 -> 7", and a 16-warning list with the same long sentence per item (S6-27). Positive: the tracks and vias appear on the preview (S6-28) and the Layout badge turns red with the count. Fix: Board check panel with groups; "new from routing" counts.
- C119: Same as C120/C122 pattern: the finding is visible only as text, no marker on the preview, no button "show on board" or "fix". UI cause: pcb preview has no overlay layer for DRC positions (previews.js pcb renderer). Fix: a "Show problems" toggle in the Layers menu that draws markers for the first group.
- C120: Real problem. Table is good content-wise but all fixes are manual Altium and in the narrow chat it is cut (S6-32). The app points to Altium, not to Outputs, and does not say whether ordering is possible. Fix: per-group state (Tool can fix / You fix / Accept) on the page; the chat answer ends with the decision "can I order with this?" in one sentence.
- C121: Real problem. No accept/waive control; the red 421 stays forever. Fix: Accepted risks per group, like DFM.
- C122: Real problem. The checklist is text-only; the second question ("can you do it?") is answered "No" after 2 steps. A student with no Altium experience has no path in the browser. Fix: the three-state model above; for "You fix in Altium" items show numbered steps with a "Done" button that re-runs Check board.

## Round 2 (C123-C130, rules edits and re-routes)
- [WRONG] A skipped rule is reported as success: C125/C126 ("1 added, 0 updated, 2 skipped (PlaneClearance, M3_Holes_Plane_Gap)"; the Rules badge clears and the page says it matches while the hole rule is NOT in Altium). The Extra rules form offers kinds the importer cannot write (Plane clearance, Differential pair) with no hint.
