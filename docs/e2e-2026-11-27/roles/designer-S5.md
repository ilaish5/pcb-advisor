Reviewed: S5-01..S5-27 (key screens opened: 03, 07, 12, 14, 16, 18, 20, 23, 26, 27), roles/student.md S5, confusions C99-C109. Source greps in `ui/js/`.
Flow: switch engine -> set board size (button, ~30 s) -> ask for 4-layer stack and holes (cannot) -> Place parts (50 s) -> read warnings -> ask distances (2 rounds) -> re-place with a "yes" (refused once) -> look at the preview. The stage is a good UI base (a real preview, clear step buttons) held back by what the tool cannot do and by an unreliable status banner.

## How the UI handles what it cannot do (layer stack, moving a part near a pin)
- Layer stack (S5-06, S5-07, S5-27, C100, C109): the agent says in prose "I can't set the stack up for you ... open Design > Layer Stack Manager (D > K) ..." and cites a course file "not in Sources". The Layout page has no control for it and no indicator of the real stack. Worse, the header "4 copper layers" (S5-12, S5-26, S5-27; source previews.js:760-762, which reads `data-copper-layers` or `b.layers`, the project SETTING) looks like a fact about the board, but the agent then says "the real stack is unknown". The page presents a setting as a measurement. Fix: the header shows the verified state: "4 layers (from the file)" or "Stack not verified: project setting 4" in amber, and a one-click "Check stack" that reads it.
- Moving a part near a pin (S5-16, S5-18, S5-22, C103, C106, C107): "Place parts can't put single parts at a pin ... someone else must move them in Altium". The UI offers no move control, no "needs a manual move" list, and the end of every answer is "Next: move Y1 and C13 in Altium, then press Route board". The Route board button stays the same; the page does not record that 3 parts still need a hand move.
- Same missing pattern as stages 3-4: there is no persistent per-item state "tool can fix / you fix in Altium (steps + Done) / ignore (reason)". Here it would be a "To move by hand" list on the Layout page: Y1 (8.1 mm from U1-6, limit 5), C13 (4.9 mm, limit 3), C10 (15.7 mm), each with its measured distance, a checkbox "moved", and a "Re-measure" button that updates the numbers. The Route board button should warn "3 parts still marked too far" instead of silently going on.
- The keep-out case is a model of how NOT to do it (S5-12, S5-16, C101, C104): the first banner said "run library.build, then place again"; the next message corrected itself ("a correction to my last reply: the library build does not add the corner keep-outs, draw the four rectangles yourself"), and a third told the student not to accept Altium's Update PCB removals (S5-20). Three contradicting instructions on one item in four minutes; one of them an Altium-only step the student never sees in the web UI.

## Can the student see the board well enough to judge placement?
Partly yes, and this is the strongest UI element of the stage: S5-12/S5-14 show the outline, red top-layer pads and silk outlines, named mounting holes (H1-H4, KO1-KO4 after the second placement, S5-20), colored layer chips (Top / Bottom / Through-hole), a Layers menu, zoom and Fit. A student can see "connectors on the long edges" (C102) and "right third empty" at a glance. What is missing for judging placement:
- No measurement. The student cannot click a cap and see "1.8 mm to U1 pin 36". The distances exist only as a chat table (S5-16, S5-22) that the student asked for by hand; two answers disagreed (S5-23, C108). Fix: click a part -> panel with nets, distances to the pins it serves, pass/fail against the rule; "Show distances" overlay with a line from each decoupling cap to its pin, colored green/amber/red. UI-SPEC tab 4 already asks "click a part or net and ask".
- Labels (J1, J2, Y1...) are drawn away from their footprints (S5-14, C102), and small parts crowd one side; at Fit, pad numbers and nets are not visible. Fix: label next to the part, pin names on zoom, net highlight on hover.
- No marks for what failed: the 8 warnings sit in a collapsed banner ("Show 8 warnings"), while the preview shows no marker at Y1, C13, C10. Fix: warning icons on the board at the offending parts, linked to the list.
- The preview shifted under the student's click (S5-24, S5-25, C108): a chat button was clicked and the page re-laid-out so the click opened J2's part panel. Layout shifts after an answer arrives must be avoided (reserve space, or do not move the page while the pointer is over it). Source: re-render of the center on state change (ui/js/views/previews.js pcb view `renderCenter`).

## Findings
- [WRONG-looking state] Success wording over failures: S5-12 banner "Altium: 55 parts placed, outline kept, saved and checked against the netlist" (C101) while 8 warnings include unplaced keep-outs and a crystal 8.2 mm from U1; the same phrase after the second placement (S5-20, 4 warnings). "Checked against the netlist" is a connectivity statement; the student reads it as "the placement is good". Fix: banner = "Placed 55 parts. 4 things to look at" in amber, never green-adjacent wording; if a rule failed the first line says "Placement does not meet N rules". Source previews.js banner builder near the `PV_STEPS` result text (:330-340).
- [FRICTION] The consent flow disagrees with the buttons: S5-17, S5-18 (C105). The Place parts button asks for confirmation itself ("Replacing removes the parts and copper ... a backup is kept", previews.js:335) and "the click is the consent", but in chat the agent asks "Replace the placement? Answer yes/no" in free text, refuses a "yes" that came inside a longer sentence, and shows a red error "altium.place_pcb: not run, student_said must be a verbatim quote of ONE student message ... (the message... more)". Three UI faults: internal parameter names in a student error; the question has no Yes/No buttons although the chat already supports quick replies (chatSuggestionItems, chat.js:608-617, `last.ask`); and a long yes is rejected. Fix: render "Replace the placement? [Yes, replace] [No]" as buttons; hide the technical text.
- [FRICTION] Contradictory answers to one question (S5-16 vs S5-23, C108, C107): the table says C19 28.5 mm and C6/C7 18-22 mm; the follow-up says C10 is the only cap over the limit and the rest are within 5 mm. The second answer also carries "(Not run: follow-up replies do not run actions: chat.ask)" (internal text, S5-23). Fix: numbers come from one measurement object rendered in the UI (see above), not re-derived in prose; hide "Not run" internals.
- [FRICTION] Board size and layers start wrong: S5-03/S5-04 (C99). Layout opens with "2 copper layers" and a 152.4 x 101.6 mm default board and a banner "the idea says 60 x 45"; "Set board to 60 x 45" greys out ~30 s with no message (S5-04); the Idea page still said 45 x 35 earlier (C96). The idea was confirmed with 4 layers and a size; the first Layout visit should apply or at least propose both together: "Set board: 60 x 45 mm, 4 layers". Source previews.js:790 (the outline resize button) and the banner next to it.
- [FRICTION] Long waits: Place parts 50-60 s is good and showed "Placing..." feedback; but follow-up questions about distances took minutes with bare "Working..." (C94-C95 in stage 4 similar). Same wait-feedback finding as every stage.
- [FRICTION] Step order text is stale: after the first placement the chip is "Help me with the next step: Route the board" (S5-12, S5-14) although 8 warnings and unplaced keep-outs are open, and later "Route the board now, or wait until C10 has been moved?" is a question without buttons (S5-23). Fix: chips derived from open items; a two-option question gets two buttons "Route now" / "Wait".
- [FRICTION] Unrequested/unclear Altium-only instructions: "When Update PCB offers to remove H1-H4 and KO1-KO4, do not accept" (S5-20). The student does not see Update PCB at this stage; the instruction cannot be followed from the web UI and appears with no context. Fix: shown only where it applies (when the student presses Update PCB, or in the Outputs checklist).
- [COSMETIC] Rules badge 6 -> 8 and Outputs badge 1 appeared during placement (S5-12, S5-26) without a tooltip: the unexplained badge finding again.
- [COSMETIC] Preview chip "Through-hole" orange for mounting holes is fine, but KO01-KO04 text inside the orange circles is too small to read at Fit (S5-26).
- Good: a real, interactive preview with Top/Bottom/Through-hole chips and a Layers menu; Place / Route / Check board / Next in one header row with one primary; "a backup is kept" stated on destructive replace; sheet tabs and part panel on click; the placement preview is fast (50-60 s) with progress text "Placing..".

## Confusions C99-C109: answers
- C99 REAL. Layout does not start from the confirmed Idea (2 layers, default board) and the size button has no feedback for ~30 s.
- C100 REAL. The app cannot set the stack and offers no control and no verification; the instruction cites a course file "not in Sources". The holes appear only as keep-out RULES on the Idea page, not as board objects. Fix: one "Prepare board" step (size + stack + holes) with a visible result list, or an honest "These need Altium: [steps] [Done]".
- C101 REAL. "Checked against the netlist" success wording over 8 warnings; the keep-out failure told the student to run Build library (BOM page) and place again.
- C102 REAL (UI side). Connectors on the long edges is placement content; but the labels away from footprints and no pin/net overlay are UI problems. 
- C103 REAL. The distance table exists only because the student asked; the banner said "checked". The placer's pin-awareness limit is for the engineer.
- C104 REAL. Self-contradicting keep-out instructions in four minutes (wrong first instruction corrected later).
- C105 REAL. Verbatim-quote refusal with internal parameter names; no Yes/No buttons.
- C106 REAL. Re-placing made C13 worse (3.9 to 4.9 mm) with no before/after comparison; "do not accept removals" is Altium-only. Fix: re-place shows a before/after table; the previous placement stays restorable (backup exists: expose "Restore previous placement").
- C107 REAL (UI side). No per-pin rule display; second placement worse on several caps and the student only learns it by asking. Content/algorithm for the engineer; UI: show the rule results automatically after every placement.
- C108 REAL. The page shifted under the click (S5-24/S5-25) and the follow-up answer contradicted the table; "Not run: follow-up replies do not run actions" is leaked internal text.
- C109 REAL, important. "4 copper layers" is a setting displayed as fact (previews.js:760-762); the real stack is unknown; no UI to read or check it. Fix as above.
- (C93-C98, stage 4 round 2, answered here for completeness:) C93 REAL: the "prove it" for 3 sheets = one circuit lives only in Altium; add a "Check connectivity" result to the Schematic header (compiled net count, cross-sheet nets, split/merge 0). C94 REAL: a proposed pull-up needs a BOM card AND a netlist rewrite AND a redraw; show it as one change with one approval. C95 REAL: notes written to notes.md are invisible in the UI; show them on the Idea/Outputs page. C96 REAL: Set updates the board but not the Idea text; two places disagree (same as C43/C46). C97 PARTLY content (placer rules); UI: state the real limits on the Layout page ("checks distance to any pad within 5 mm, not per pin"). C98 REAL: a free-text "replace Main?" confirmation and a redraw that rewrote 3 sheets' worth of facts for one resistor; scope the redraw to the changed part and show a one-line result.

## Score and fixes
Score S5 (UI/UX only): 5.5/10. The preview, step buttons and the 50-second placement are good. The score is held back by a status banner that says "checked" over failures, a header that presents a setting as the real layer stack, no way to see or measure the placement against the rules, a consent flow that refuses a yes with an internal error, and no home for the "you must do this in Altium" items.

Top 3 fixes:
1. Make the Layout page tell the truth and show the rules: banner wording "Placed 55 parts, N rule failures" (amber), header shows verified vs setting for the layer stack, and a rules panel with per-part distances and warning markers on the board that update after every placement (ui/js/views/previews.js:330-340 banner, :755-790 header/meta, pcb preview renderer).
2. Add the "tool cannot do this" list with steps, Done, and Re-measure to the Layout page, and have Route board warn about open items (ui/js/views/previews.js, chip logic ui/js/chat.js:608-617).
3. Fix the confirmation flow: Yes/No quick-reply buttons for any agent yes/no question, hide internal parameter names ("student_said", "chat.ask", "not run"), and stop page re-layout from stealing clicks (ui/js/chat.js:608-617 `last.ask`, ui/js/views/previews.js re-render).
