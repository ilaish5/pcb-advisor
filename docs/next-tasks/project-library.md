# Project library: the tool downloads what it can, builds what is missing, hands the student one IntLib

Goal (user, 2026-10-21): every project gets a complete, correct Altium library made by the tool, not by the
student. Today `scripts/library.py` only writes search links and a build script that assumes the part files
already exist, so the agent sends the student to Ultra Librarian / SnapEDA (log-in sites). Found in the
Night-light student E2E: all 15 BOM lines "No model", the flow stops before the schematic.

The method is the one that worked on the kiln board (`C:\Users\Public\Documents\Altium\ceramic_controller\.claude\skills\`
`altium-part-sourcing`, `altium-library-builder`, read-only reference; read their SKILL.md, reference/pitfalls.md,
reference/formats.md and scripts). Port the ideas, not the project paths.

## Design decisions
- Sources per BOM line, in order:
  1. EasyEDA by the line's LCSC C-number, via `easyeda2kicad` (pip dependency, run as a subprocess, no login,
     verified 2026-10-21 for C7955: symbol + footprint + STEP). Downloaded files are untrusted data.
     A failure or a block is reported, never worked around.
  2. Generated by the tool when there is no C-number or no EasyEDA model: an IPC-7351 nominal footprint for
     standard packages (0402/0603/0805/1206 chip R/C/L/LED, SOD-123, SOD-323, SOT-23-3/5/6, SOT-223, SOIC-8/14/16,
     TSSOP-8/14/16/20, 2.54 mm pin headers 1xN/2xN) and a symbol: the standard R, C, L, LED, diode, NPN/PNP,
     N/P-MOSFET shapes for 2-3 pin parts, else a box with the pins the project's netlist sheet lists for that ref
     (number, name, type), inputs left / outputs right / power top / GND bottom.
  3. Log-in sites (Ultra Librarian, SnapEDA, SamacSys; user, 2026-10-21: "ask the student to log in once"):
     the tool opens the part's page in the student's browser, the student logs in (once) and downloads the
     Altium/KiCad zip, the tool picks the new zip up from Downloads (like `jlc.pickup`) and imports it. The tool
     never types a password or solves a CAPTCHA. Used for parts that 1 and 2 cannot cover, or a better model.
  4. Still missing: status "missing" with what the student can provide; the manifest says so; nothing invented.
- Lines with the same package share one footprint (the design is per footprint; the MPN can change at order
  time without touching the board).
- Every part gets the kiln fixes when it is added: 2-pin parts show pin numbers only (names hidden); passives'
  pins Passive, power pins Power; pins on the 100 mil grid; parameters MPN, Manufacturer, LCSC, Description
  (value, rating, "LCSC Cxxxx"), Comment (value for R/C/L, else MPN); designator prefix from the BOM ref;
  footprint silk >= 0.15 mm; footprint names unique; links by name, never by file path; coordinates relative
  to the library origin (never +50000 mil); KiCad y down vs Altium y up; KiCad pin `at` = connection end.
- Where files live: downloads, specs and `manifest.json` in `projects/<name>/library/` (project data, never in
  the repo). The Altium library (`<Project>-Lib.SchLib`, `.PcbLib`, `3D/`, `.LibPkg`, compiled `.IntLib`) next to
  the linked Altium project, in `<altium project folder>/Library/`.
- The tool builds the Altium files through `scripts/altium/bridge.py` (AdvisorBridge.pas), not an MCP. The batch
  symbol/footprint creation can be ported from `C:\Users\ilaish\Documents\altium-mcp\server\AltiumScript\`
  (MIT, Siddharth Ahuja: keep the notice in the ported file) and the kiln `LibTool.pas`.

## Stages
- L1 (Python only, no Altium): fetch, convert (port kicad2spec), generate, per-package sharing, manifest,
  checks (port check_lib for the spec level), CLI `python scripts/partlib.py prepare|status <project>`. Tests.
- L2 (Altium): bridge commands to create SchLib/PcbLib from a template, footprints and symbols from the specs,
  link, parameters, pin types/names, 3D attach, LibPkg, compile and install; verify counts read back from the
  files. Live run on Night-light.
- L3: vendor zip pickup from Downloads (source 3) and import through the same convert path; agent action `library.build`, Library page per part (symbol / footprint / 3D / source / status), AGENTS.md
  and the project-library + part-models skills rewritten (the tool builds; the student checks and places).
  Then continue the Night-light E2E to Gerbers.
