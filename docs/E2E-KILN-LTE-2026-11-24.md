# E2E acceptance: new kiln controller (LTE) through the UI — 2026-11-24

Tested build: main at 137dc00 (server http://127.0.0.1:8931). Tester: Claude Sonnet 5.5 acting as the student, in Claude in Chrome (Windows, one new tab, viewport 1320x540). Project: `Kiln-LTE-2026-11-24`.
Rules I kept: only the UI's own buttons and chat; no code fixed; no JLC cart/order/login; no "Allow and retry" ever clicked; no manual downloads. Altium was driven only by the system (bridge log `altium-log.jsonl`); Altium results below come from the bridge log, the files on disk and DRC, not from looking at Altium.
Screenshots: `docs/img/e2e-kiln-lte/01…23`. Times are wall-clock on 2026-11-24. Click counts are my own estimates.

## 1. Bottom line

The student **cannot finish this board** with the system as it is. Idea, BOM, library, schematic and placement work (with a lot of friction). **Routing fails, Gerbers/outputs are refused, and no workaround exists inside the system.** Two hard blockers, both found by a perfectly ordinary design:

1. **Routing**: 2-layer router fails on 12 nets (SCK, SDI, USB_DM, MDM_PWR, BT1–BT5, SDA, STOP, GND) on a 100x80 board with 93 parts, and it restores the board all-or-nothing (even the system's own "route the rest and leave X open" button restores). Final board has **0 tracks**.
2. **Layers/size**: the Idea confirmed a 4-layer board (the agent itself proposed and wrote it), but the system supports only 2 layers; nobody said so at Idea stage. The outline cannot be changed after creation; the idea now says 120x90, the PcbDoc says 100x80.

A third blocker for a real order: outputs and the Gerber zip are refused while pins are unverified. I pressed the system's own "Fetch datasheets" (it downloaded datasheets itself, no login): 24 parts became **22 unverified + 1 real conflict (U8)**, but the remaining 22 are not wrong pins — the checker cannot read the datasheet (no pin table in the text, package mismatch, CJK text for U6, part name with "+"). They can only be cleared by the student confirming each by hand ("Confirm all (22)" exists; I did not press it, because I had not checked them). Because of this gate, **I could not test whether the system would generate Gerbers for an unrouted board**.

## 5. Ranked friction (what costs the student most)

1. **Schematic stage took 67 min** and needed 8 messages: oversize symbols make Draw refuse *every* sheet at once ("Nothing was drawn at all"); the fit check runs only inside Draw, so the agent cannot pre-test; the agent re-splits sheets by trial and error.
2. **The route stage costs ~5 min per attempt and always ends in "restored"**: four attempts, zero tracks, no partial result, no diagnostic the student can act on (what to move?). All-or-nothing even on the "leave open" button.
3. **Agent turns that go silent**: one turn ~7 min of reading source files, then "The agent stopped answering (no output for 180s)" with Continue/Retry; the student sees tool names, regexes and file paths from inside the system.
4. **Wrong or stale facts in the UI**: counters (28 issues / 5 / 6 open / 48 to verify / 24 / 26 / 15) disagree; stale banners ("no netlist sheet", "Sheet 03 cannot be drawn") remain after the cause is gone; BOM banner reports C19, then "93 vs 102".
5. **The layer question was never raised**: 4 layers were agreed in the Idea, and only at route time (≈2 h in) did the student learn the tool supports only 2.
6. **Permission cards for scripts** ("Allow and retry" for Temp/jlc_batch.py, fitcheck.py, schematic.py) appear in the chat and look like a request to the student; I did not click them. The agent worked around them, but the chat carried confusing lines ("not run in the retry", "Stopped: no action was sent with this reply…").
7. **Misread chat**: "I cannot draw by hand" was understood as "I will draw by hand"; all five draw requests were refused with the line "The student said they will do it themselves".
8. **Error banners render one word per line** (route failure) and the action buttons overlap the text/tooltips (screen 18).
9. **Tiny viewport (1320x540)**: wide tables and the stage rail are cramped (my environment, not necessarily the system's).
10. **Idea text keeps the old project's numbers** (ceramic-controller relay budget); the Board-size fields stay blank until Save.

## 7. What a student must finish by hand

1. Get a bigger or 4-layer board: redraw the outline and layer stack in Altium (agent: Layer Stack Manager D>K), or accept 2 layers and re-place with more room around J9 and U3.
2. Route the 12 failed nets by hand (SCK, SDI, USB_DM, MDM_PWR, BT1–BT5, SDA, STOP) and add the GND bottom pour; re-run DRC (370 now, mostly Un-Routed Net).
3. Delete the 9 orphan BOM lines (J2, J3, U10, R1, R22–R24, C29, C30) by hand, or do not export the JLC BOM before that.
4. Check every pin of the 22 unverified parts against the datasheets and then confirm; look at U8 pin 7; tie U4 BIAS correctly; add the 1 k reset resistor if you still want it.
5. Check the cross-sheet nets (SCL, SDA, STOP …) in Altium and add ports if they are not joined.
6. Check the LTE bands for the chosen operator (WH-LTE-7S1 has no B7/B20) or draw the A7670G by hand.
7. Fix silk-to-solder-mask (31), sliver (91), annular ring (4), silk-to-silk (8), board clearance (2) DRC items; then generate Gerber/OutJob.
